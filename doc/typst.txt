== #fa-code 项目1：Augury--桌游规划与结算引擎

=== 技术栈

Python + Pydantic + LangGraph + LangChain + RAG 混合检索 + OpenSpec

=== 项目简介

这是一个面向桌游主持场景的规则规划与结算引擎项目，目标是把主持人的自然语言指令转化为稳定、可验证、可执行的规则任务。系统会先把指令整理为清晰的任务说明，再翻译为可供引擎执行与校验的结构化执行步骤，最终完成桌游状态读取、规则判断、骰子求值与结果写回。

项目按驾驭工程范式进行设计与开发：通过工作流编排、工具边界、结构化结果、执行校验与人工接管机制，为智能体提供可调试、可验证、可演进的运行支架。

=== 核心模块

- *Planner*：接入大模型。负责任务理解、规则检索、状态绑定与执行计划生成，是自然语言输入到结构化结算任务之间的核心桥梁；
    - *TaskNode*：负责理解主持人的自然语言指令，提炼任务目标、所需状态、判断顺序、预期结果与信息缺口；
    - *DslNode*：负责把任务说明翻译为统一的结构化执行任务JSON，保证上游规划结果能够稳定衔接后续校验与执行；
    - *Tools*：提供 `grep`、`search`、`reads`、`lint` 等工具，用于状态路径查找、规则检索、上下文绑定与执行结果校验；
- *Engine*：负责执行结构化任务步骤，处理骰子、表达式求值、规则结算、资源消耗与状态变更提交；
- *Storage*：负责世界状态的存储、读取与更新，为 planner 和 engine 提供统一、可追踪的状态访问接口。
- *Human-in-the-loop*：负责在信息缺失、规则冲突、目标对象不明确、范围覆盖难以自动确认或最终状态提交前等关键节点发起人工确认、补充与裁决，保证复杂场景下系统输出可控、可解释、可复核。

=== 功能简介

- *自然语言任务规划*：面对主持过程中高自由度的自然语言输入，系统先梳理“谁做了什么、依赖哪些前提、会产生哪些影响”，再生成清晰的执行计划，为后续结算提供稳定输入；
- *规则与状态工具集*：在规则密集场景中，系统通过混合规则检索、世界状态获取、路径绑定与执行前校验等工具能力，主动补齐规则依据和关键状态，避免在信息不足时直接猜测；
- *结构化任务 JSON*：系统将任务说明翻译为统一、明确、可校验的结构化任务 JSON，用于承载执行顺序、参数、状态引用和预期动作，并交由 Engine 完成骰子求值、规则结算和状态写回；
- *人机协作机制*：在信息缺失、规则冲突、目标对象不明确、范围覆盖难以自动确认或最终状态提交前等关键节点，系统支持主持人介入进行补充、确认与裁决，使复杂场景下的规划和结算过程既能利用自动化能力，又保留人工把关与最终控制权。
