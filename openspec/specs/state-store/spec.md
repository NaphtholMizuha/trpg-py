## 目的
定义独立于 `engine` 的状态存储能力边界、点路径访问语义，以及执行器与引用解析逻辑对状态存储接口的依赖方式。
## 需求
### 需求:统一状态存储接口
系统必须提供一个独立于 `engine` 的状态存储包，并且该包必须只通过 `read`、`reads`、`write`、`writes`、`mod`、`mods`、`keys` 七个接口暴露点路径状态访问能力。

#### 场景:调用方读取单个路径
- **当** 调用方请求一个点路径对应的状态值
- **那么** 状态存储包必须通过 `read` 返回该路径对应的当前值或抛出明确的路径错误

#### 场景:调用方批量读取多个路径
- **当** 调用方一次请求多个点路径的状态值
- **那么** 状态存储包必须通过 `reads` 返回与请求路径集合一一对应的读取结果

#### 场景:调用方写入单个路径
- **当** 调用方请求更新某一个点路径上的值
- **那么** 状态存储包必须通过 `write` 完成原子写入，并保持与现有点路径语义一致的深拷贝与路径校验行为

#### 场景:调用方批量写入多个路径
- **当** 调用方在一次操作中提交多个路径写入
- **那么** 状态存储包必须通过 `writes` 按定义顺序应用这些写入，并在返回结果中允许调用方获知最终写入值

#### 场景:调用方基于旧值修改路径
- **当** 调用方需要基于当前路径值计算新值
- **那么** 状态存储包必须通过 `mod` 或 `mods` 读取当前值并生成新值后再写回，而不是要求调用方自行拆成先读后写

#### 场景:调用方全量枚举路径
- **当** 调用方请求当前状态的路径枚举结果且不提供范围过滤参数
- **那么** 状态存储包必须通过 `keys` 返回可枚举路径集合

### 需求:兼容现有点路径语义
状态存储包必须兼容当前点路径解析和状态结构约定，包括字典键、列表索引、数字字符串键及缺失路径错误语义。

#### 场景:访问列表索引与数字字符串键
- **当** 调用方读取或写入包含数字 token 的点路径
- **那么** 状态存储包必须延续现有规则，优先兼容字典中的数字字符串键，并在适用时支持列表索引访问

#### 场景:访问不存在的路径
- **当** 调用方请求读取不存在的路径或写入非法中间节点
- **那么** 状态存储包必须抛出与当前语义等价的路径错误，而不是静默返回空值或自动创建非法结构

### 需求:engine 通过状态存储接口访问状态
任务执行器、操作分发器与引用解析逻辑必须通过状态存储包的公开接口访问状态，而禁止继续直接依赖 `engine` 内部路径工具实现。

#### 场景:executor 提交变更
- **当** executor 提交 `OperationResult.changes`
- **那么** 它必须通过状态存储接口完成旧值读取与新值写入，并继续生成与当前结构兼容的 `AppliedChange`

#### 场景:refs 解析状态引用
- **当** `resolve_reference` 解析 `context`、`state` 或 `result` 命名空间的点路径
- **那么** 它必须复用状态存储接口或同一语义层，而不是维护另一套独立路径访问实现

### 需求:状态存储必须支持按范围枚举路径
状态存储包必须支持按范围（例如 `prefix`）枚举路径，用于上层工具按需发现可引用状态路径，禁止只支持全量读取后由调用方自行过滤。

#### 场景:调用方按前缀枚举路径
- **当** 调用方提供一个路径前缀进行枚举
- **那么** 状态存储包只返回匹配该前缀的路径
- **那么** 返回路径格式与现有点路径读写语义一致
