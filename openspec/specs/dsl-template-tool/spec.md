# dsl-template-tool 规范

## 目的
待定 - 由归档变更 require-explicit-template-tool-calls 创建。归档后请更新目的。
## 需求
### 需求:template 必须作为真实 agent 工具调用暴露
系统必须将 `template` 作为 `dsl_node` agent 可直接调用的真实工具暴露，禁止仅由宿主代码在 agent 运行前预取模板结果并伪装成工具能力。

#### 场景:dsl_node 查询模板
- **当** `dsl_node` 需要某类任务族的合法 DSL 骨架
- **那么** agent 必须能够直接调用 `template`
- **那么** 模板查询不得要求宿主在 agent 调用前先完成同等查询

### 需求:template 工具调用必须可观察
系统必须为 `template` 提供与 `lint` 类似的可观察性，禁止真实运行时完全看不出 `template` 是否被调用。

#### 场景:template 工具完成一次查询
- **当** agent 调用了 `template`
- **那么** 系统必须记录该次查询的受控枚举字段或等价诊断信息
- **那么** 系统必须记录本次查询是否命中模板
- **那么** 系统必须在命中时记录 `template_id`
- **那么** 系统必须在发生回退时记录回退状态

### 需求:系统必须为 dsl_node 提供 template 工具
系统必须提供一个名为 `template` 的只读工具，供 `dsl_node` 在生成 `TaskDocument` 时按需查询合法 DSL 模板。系统禁止继续让 `dsl_node` 只能依赖长 prompt 中内联的完整 DSL 模板手册。

#### 场景:dsl_node 查询范围法术模板
- **当** `dsl_node` 已识别当前任务属于范围法术伤害一类
- **那么** 节点必须能够调用 `template` 工具查询对应模板
- **那么** 工具必须返回该任务族的合法 DSL 骨架与绑定规则

### 需求:template 工具输入必须使用受控枚举字段
系统必须要求 `template` 工具的输入使用少量受控枚举字段，禁止让模型通过自由文本或自由拼接的签名字符串查询模板。

#### 场景:调用方传入模板查询参数
- **当** 调用方向 `template` 工具传入任务模板查询
- **那么** 输入必须使用如 `task_family`、`resolution_mode`、`success_rule`、`resource_mode`、`targeting_mode` 这类受控字段
- **那么** 每个字段必须来自系统定义的有限枚举值集合
- **那么** 工具不得要求调用方构造自由文本 `template_signature`

#### 场景:调用方无法细分全部枚举字段
- **当** `dsl_node` 已能识别一级任务族但无法安全细分某个二级字段
- **那么** 调用方必须可以传入 `unknown` 或等价保守值
- **那么** `template` 工具必须返回与该保守值兼容的回退模板，而不是直接失败

### 需求:template 工具输出必须包含合法 DSL 骨架与绑定说明
系统必须要求 `template` 工具返回的信息足以让 `dsl_node` 在不重新发明结构的前提下填充 DSL。系统禁止工具只返回一个模板名称而不附带可执行骨架。

#### 场景:template 返回模板结果
- **当** 调用方成功命中某个模板
- **那么** 结果必须至少包含 `template_id`
- **那么** 结果必须包含 `step_order` 与 `dsl_skeleton`
- **那么** 结果必须包含 `required_bindings`
- **那么** 结果必须包含 `binding_rules`
- **那么** 结果必须包含 `common_mistakes`

### 需求:template 工具第一版必须覆盖少量高频任务
系统必须要求 `template` 工具在第一版至少覆盖少量高频任务族，以改善当前 `dsl_node` 最常见的失败样本。系统禁止在第一版宣称覆盖全部任务类型。

#### 场景:第一版模板覆盖范围
- **当** `template` 工具首次对外提供模板能力
- **那么** 它至少必须覆盖单体武器攻击
- **那么** 它至少必须覆盖单体豁免伤害法术
- **那么** 它至少必须覆盖范围法术伤害
- **那么** 它至少必须覆盖单体治疗或治疗增益
