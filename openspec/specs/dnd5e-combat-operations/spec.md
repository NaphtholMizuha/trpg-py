## 目的
定义 DnD5e 判定解析器中的原子操作能力边界、统一输入输出约定，以及选择、检定、伤害、治疗、资源与效果处理的规则语义。
## 需求
### 需求:原子操作必须遵循有限的步骤类型分类
系统必须将原子操作组织在有限的步骤类型分类之下，至少包括 `select`、`check`、`damage`、`heal`、`resource`、`effect` 和 `state`。操作的具体行为差异必须通过 `kind` 进一步区分。

#### 场景:步骤按 type 与 kind 分派
- **当** 调用方提交一个 `type=damage`、`kind=apply` 的步骤
- **那么** 系统将其识别为伤害结算步骤
- **那么** 系统按对应的伤害操作逻辑处理其输入

### 需求:选择类原子操作必须支持单体与范围目标查找
系统必须提供选择类原子操作，用于直接确定单体目标或依据范围、阵营和过滤条件查找目标集合。选择结果必须以统一结构返回，至少包含 `target_ids` 数组。若选择步骤声明了目标选取距离校验，系统必须在产出目标集合前先完成该校验。

#### 场景:范围查找返回多个有效目标
- **当** 调用方执行一次球形范围选择，中心点与半径覆盖三个敌对生物
- **当** 选择条件排除施法者本人
- **那么** 该操作输出包含这三个目标标识的 `target_ids`
- **那么** 输出结果中不包含施法者标识

#### 场景:单体目标超距时选择失败
- **当** 调用方执行一次 `select.target`
- **当** 该步骤声明 `targeting.max_range=5`
- **当** source 与 target 的实际距离大于 5
- **那么** 该步骤执行失败
- **那么** 该步骤不得返回伪造的 `target_ids`

### 需求:选择类原子操作必须支持基础过滤条件
系统必须支持在目标选择时按阵营、标签、显式排除列表和存活状态过滤候选对象。若过滤后无目标，操作必须返回空集合，而不是伪造默认目标。

#### 场景:按阵营与存活状态筛选范围目标
- **当** 范围内同时存在友方、敌方和已死亡单位
- **当** 选择操作要求仅保留存活的敌方单位
- **那么** 输出的 `target_ids` 仅包含存活敌方单位
- **那么** 不符合条件的单位不会出现在结果中

### 需求:选择类原子操作必须支持 `field_map`
系统必须允许选择类原子操作通过 `field_map` 显式声明候选对象的逻辑字段映射，包括但不限于 `id`、`side`、`alive`、`tags`、`position.x` 和 `position.y`。系统不得强制候选对象必须使用固定字段名。若 `select.target` 声明了距离校验，系统必须能够通过 `field_map` 读取目标位置。

#### 场景:范围选择通过 field_map 读取自定义坐标字段
- **当** 候选对象的横纵坐标分别存放在 `space.grid.col` 和 `space.grid.row`
- **当** 选择步骤通过 `field_map` 声明 `position.x -> space.grid.col` 与 `position.y -> space.grid.row`
- **那么** 系统按映射后的字段读取坐标
- **那么** 该步骤仍可正确完成范围筛选

#### 场景:单体目标通过 field_map 读取自定义坐标字段
- **当** `select.target` 需要校验目标距离
- **当** 目标坐标位于自定义字段且步骤提供了 `field_map`
- **那么** 系统按映射后的字段读取目标位置
- **那么** 系统据此完成 source 到 target 的测距

### 需求:选择类原子操作必须支持显式 targeting 距离校验
系统必须允许 `select.target` 与 `select.area` 在 `args` 中通过 `targeting` 对象显式声明距离校验输入。`targeting` 至少必须支持 `source_position`、`max_range` 和 `range_metric`，系统不得要求调用方把测距规则隐式编码在其他业务字段中。

#### 场景:范围选点显式声明 targeting
- **当** 调用方执行一个 `select.area` 步骤
- **当** 该步骤提供 `targeting.source_position`、`targeting.max_range` 和 `targeting.range_metric`
- **那么** 系统将其识别为需要先执行目标选取距离校验
- **那么** 后续范围解析以该校验结果为前提

### 需求:单体目标选择必须按 source 到 target 的距离校验
系统必须在 `select.target` 声明了 `targeting` 时，使用 `targeting.source_position` 与目标位置进行测距。目标位置必须来自被选目标及其 `field_map` 映射，而不是来自范围原点或其他间接字段。

#### 场景:近战攻击目标在合法距离内
- **当** 调用方执行一次 `select.target`
- **当** source 与 target 的实际距离小于或等于 `targeting.max_range`
- **那么** 该步骤执行成功
- **那么** 输出的 `target_ids` 包含该目标标识

### 需求:范围目标选择必须按 source 到 origin 的距离校验
系统必须在 `select.area` 声明了 `targeting` 时，使用 `targeting.source_position` 与该步骤的 `origin` 进行测距。系统不得用范围内候选对象的位置替代 `origin` 参与这一步校验。

#### 场景:火球术选点超距时选择失败
- **当** 调用方执行一次 `select.area`
- **当** source 与 `origin` 的实际距离大于 `targeting.max_range`
- **那么** 该步骤执行失败
- **那么** 该步骤不得继续进行范围内目标收集

### 需求:目标选取校验必须区分超距失败与合法空结果
系统必须将“超距”与“合法但未命中任何目标”区分开。若目标或选点超距，步骤必须失败；若选点合法但过滤与范围覆盖后没有任何目标，步骤必须成功并返回空 `target_ids`。

#### 场景:合法选点但范围内没有目标
- **当** 调用方执行一次 `select.area`
- **当** source 到 `origin` 的距离在合法范围内
- **当** 范围覆盖与过滤后没有任何候选对象符合条件
- **那么** 该步骤执行成功
- **那么** 该步骤输出 `target_ids=[]`

### 需求:检定类原子操作必须使用统一的 check 描述
系统必须允许检定类原子操作以统一的 `type=check` 结构接收输入，并通过 `kind` 区分攻击、豁免、能力或技能等具体检定类别。若步骤包含标签，操作必须按受支持的标签集合解释，而不是忽略其语义。

#### 场景:以统一结构执行豁免检定
- **当** 调用方执行一个 `type=check` 且 `kind=save` 的步骤并提供 DC 15
- **当** 掷骰值与修正值之和为 17
- **那么** 系统将该步骤按豁免检定处理
- **那么** 输出中包含原始骰值、修正值、总值与目标 DC

### 需求:检定类原子操作必须返回统一的四态结果
系统必须要求检定类原子操作返回统一的 `outcome` 字段，其允许值至少包括 `success`、`fail`、`crit_success` 和 `crit_fail`。操作还必须返回原始骰值、被选中的自然骰值、修正值与总值，供后续步骤消费。

#### 场景:攻击检定返回四态结果
- **当** 调用方执行一次攻击检定
- **当** 被选中的自然骰值为 20 且该检定启用了 `nat` 标签
- **那么** 输出中的 `outcome` 为 `crit_success`
- **那么** 输出中同时保留原始骰值列表、自然骰值与最终总值

### 需求:检定类原子操作必须使用显式骰子规格与标签化掷骰语义
系统必须要求检定类原子操作接收显式骰子规格作为输入，并将优势、劣势、天然骰追踪和修正值与骰子规格分开表达。系统禁止要求调用方通过单个复杂公式字符串同时表达 `1d20`、取高/取低和修正值。

#### 场景:攻击检定使用显式 d20 与标签
- **当** 调用方执行一次攻击检定
- **当** 输入包含 `dice=1d20`、`tags=["nat","adv"]` 和独立修正值
- **那么** 系统按优势规则掷出两个 d20 并选取结果
- **那么** 输出中保留原始骰值列表、被选中的自然骰值与最终总值

### 需求:检定类原子操作必须支持显式依赖路径
系统必须允许检定类原子操作通过显式路径或路径模板声明其依赖字段，例如目标 AC、豁免修正值、能力修正值或技能修正值。系统不得要求这些值只能从固定的默认字段位置读取。

#### 场景:攻击检定通过路径模板读取目标 AC
- **当** 调用方执行一次攻击检定
- **当** 该步骤提供 `target_ac_path_template`
- **那么** 系统按模板定位目标 AC 字段
- **那么** 该检定无需依赖固定的 `ac` 字段名

### 需求:检定类原子操作必须按检定类型解释天然 20 与天然 1
系统必须按检定类型解释天然 20 和天然 1。默认情况下，攻击检定在启用 `nat` 标签时，天然 20 必须映射为 `crit_success` 且视为自动命中，天然 1 必须映射为 `crit_fail` 且视为自动失手；豁免检定与属性/技能检定默认不得仅因天然 20 或天然 1 产生 `crit_success` 或 `crit_fail`，也不得仅因天然 20 或天然 1 自动改变成功/失败结果。

#### 场景:攻击检定中的天然 20 触发暴击
- **当** 调用方执行一次攻击检定
- **当** 被选中的自然骰值为 20 且该步骤包含 `nat` 标签
- **那么** 该操作输出 `outcome=crit_success`
- **那么** 该操作输出自动命中标记和暴击标记

#### 场景:豁免检定中的天然 20 不自动成功
- **当** 调用方执行一次豁免检定
- **当** 被选中的自然骰值为 20 且总值仍低于目标 DC
- **那么** 该操作不得仅因天然 20 返回 `success`
- **那么** 该操作不得仅因天然 20 返回 `crit_success`

#### 场景:豁免检定中的天然 1 不自动失败
- **当** 调用方执行一次豁免检定
- **当** 被选中的自然骰值为 1 且总值仍高于或等于目标 DC
- **那么** 该操作不得仅因天然 1 返回 `fail`
- **那么** 该操作不得仅因天然 1 返回 `crit_fail`

#### 场景:技能检定中的天然 20 不自动成功
- **当** 调用方执行一次技能检定
- **当** 被选中的自然骰值为 20 且总值仍低于目标 DC
- **那么** 该操作不得仅因天然 20 返回 `success`
- **那么** 该操作不得仅因天然 20 返回 `crit_success`

### 需求:优势与劣势标签必须归并为三态掷骰模式
系统必须将 `adv` 与 `disadv` 作为独立标签输入处理，并在执行前归并为普通、优势或劣势三态模式。同侧多个优势来源或劣势来源不得叠加，优势与劣势同时存在时必须相互抵消。

#### 场景:优势与劣势同时存在时按普通检定处理
- **当** 某次攻击检定同时具有至少一个优势来源和至少一个劣势来源
- **那么** 该操作按 `normal` 模式执行
- **那么** 该操作只掷出一个 d20 作为基础检定

### 需求:伤害与治疗操作必须通过显式输入结算数值
系统必须提供伤害和治疗原子操作，能够根据显式数值、骰子结果或上一步结果结算最终变化量，并将结果写入指定状态路径。若提供了乘数、下限或上限，系统必须在写回前应用这些规则。对于治疗操作，若步骤显式提供目标生命上限路径或路径模板，或当前生命值路径可按默认布局解析到生命上限，系统必须在写回前将治疗结果限制在目标生命上限以内。

#### 场景:豁免成功后伤害减半
- **当** 伤害操作引用前序豁免结果 `success=true`
- **当** 基础伤害为 12 且步骤配置了成功豁免时乘数为 0.5
- **那么** 系统将最终伤害结算为 6
- **那么** 目标生命值按 6 点伤害被更新

#### 场景:治疗结果不会超过目标生命上限
- **当** 某个目标当前生命值为 7，生命上限为 10
- **当** 治疗操作对该目标结算 5 点治疗
- **那么** 系统将写回后的生命值限制为 10
- **那么** 系统不得把生命值写成 12

### 需求:伤害、治疗与效果操作必须支持显式写回路径模板
系统必须允许伤害、治疗与效果类操作通过显式路径或路径模板声明其写回位置，例如生命值字段或效果列表字段。系统不得要求调用方只能写入默认的 `hp.current` 或 `effects` 路径。

#### 场景:效果操作写入自定义效果列表字段
- **当** 某个目标的效果列表位于 `status.conditions.active`
- **当** 效果步骤提供 `effects_path_template`
- **那么** 系统按模板定位效果列表
- **那么** 该步骤可在不改变状态结构的前提下完成效果写入

### 需求:伤害操作必须将伤害骰与暴击规则分开表达
系统必须允许伤害操作显式接收伤害骰规格与固定加值，并将暴击作为独立输入或前序结果处理。系统禁止要求调用方通过单个公式字符串隐式编码暴击翻倍逻辑。默认情况下，暴击只能扩展伤害骰，不得重复计算固定加值。

#### 场景:暴击伤害通过独立标记扩展伤害骰
- **当** 一次伤害操作的基础伤害骰为 `1d8`
- **当** 该步骤输入 `is_critical=true`
- **那么** 系统根据配置的暴击规则扩展伤害骰结算
- **那么** 固定加值不会因为骰子规格写法不清而被重复计算

#### 场景:暴击不会重复固定加值
- **当** 一次伤害操作的伤害组件为 `1d8 + 3`
- **当** 该步骤输入 `is_critical=true`
- **那么** 系统额外掷出一组 `1d8`
- **那么** 固定加值 `3` 仅计算一次

### 需求:资源消耗操作必须阻止超额扣减
系统必须提供资源消耗原子操作，用于扣减法术位、充能、弹药或其他数值资源。若资源不足以支付成本，操作必须失败，并且不得提交任何资源扣减。

#### 场景:法术位不足时资源扣减失败
- **当** 角色的 `resources.spell_slots.1` 当前值为 0
- **当** 任务尝试消耗 1 个 1 环法术位
- **那么** 该步骤执行失败
- **那么** 法术位状态保持不变

### 需求:效果操作必须支持添加和移除状态效果
系统必须提供效果类原子操作，用于向目标写入 buff/debuff、持续时间或来源信息，并支持按标识移除效果。效果记录必须能够被后续步骤通过状态路径读取。

#### 场景:向目标添加一个持续效果
- **当** 任务执行添加效果操作，目标路径为 `actors.target.effects`
- **当** 输入效果包含 `id=bless`、持续轮数与来源
- **那么** 系统将该效果记录添加到目标效果集合
- **那么** 后续步骤能够通过状态路径读取该效果

### 需求:原子操作必须以统一结构向执行器返回结果
系统必须要求所有原子操作返回统一结构，其中至少包括 `outputs`、`changes` 和可选的 `events`。执行器必须能够在不感知具体操作内部逻辑的情况下消费这些结果。

#### 场景:不同操作共享同一结果接口
- **当** 攻击操作与资源扣减操作都执行成功
- **那么** 它们都以相同的结果结构返回输出与状态变更
- **那么** 执行器能够用同一提交流程处理两者

### 需求:选择类原子操作必须支持多种范围模板
系统必须允许 `select.area` 至少支持 `sphere`、`line`、`cone` 和 `target` 四种范围模板。不同模板必须按其所需的几何参数解析目标集合，而不是全部退化为球形距离判断。

#### 场景:线形范围命中直线上的目标
- **当** 调用方执行一个 `shape=line` 的范围选择
- **当** 两个敌对生物位于线形长度与宽度覆盖范围内，另一个敌对生物位于线外
- **那么** 输出的 `target_ids` 包含线内目标
- **那么** 输出的 `target_ids` 不包含线外目标

#### 场景:锥形范围只命中朝向内目标
- **当** 调用方执行一个 `shape=cone` 的范围选择
- **当** 两个目标位于锥形角度与长度范围内，另一个目标位于背向区域
- **那么** 输出的 `target_ids` 仅包含锥形覆盖到的目标

### 需求:伤害操作必须支持豁免成功后免伤
系统必须允许 `damage.apply` 在引用前序豁免结果时处理 `on_save=none`。当目标豁免成功且步骤声明 `on_save=none` 时，系统必须将该目标的最终伤害结算为 0，而不是保留基础伤害或减半。

#### 场景:豁免成功时完全免伤
- **当** 某个目标的豁免结果为成功
- **当** 伤害步骤配置 `on_save=none`
- **那么** 该目标的最终伤害为 0
- **那么** 该目标生命值保持不变
