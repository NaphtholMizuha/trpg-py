# reads-tool 规范

## 目的
待定 - 由归档变更 add-reads-tool-for-planner 创建。归档后请更新目的。
## 需求
### 需求:reads 工具必须驻留在 agent.tools 命名空间
系统必须在 `trpg_py.agent.tools` 命名空间下提供名为 `reads` 的工具能力，并且该能力必须可以被 Python 调用方直接导入和使用，而不是仅作为 planner 内部私有辅助逻辑存在。

#### 场景:调用方从 agent.tools 使用 reads
- **当** 开发者为 planner 或其他 agent 组装工具集
- **那么** 可以从 `trpg_py.agent.tools` 访问 `reads` 工具实现
- **那么** 调用方不需要自行封装状态值读取逻辑

### 需求:reads 工具必须包装 state-store 的 reads 能力
系统必须让 `reads` 工具复用底层 `state-store.reads` 作为状态值读取来源，禁止维护一套与现有点路径语义不一致的独立读取实现。

#### 场景:reads 返回路径对应的当前值
- **当** 调用方向 `reads` 提交一个或多个点路径
- **那么** 工具会复用 `state-store.reads` 读取这些路径上的当前值
- **那么** 返回结果中的路径语义与现有状态存储接口保持一致

### 需求:reads 工具必须显式区分命中、无命中和错误
系统必须通过稳定的结构化语义区分“至少一个路径命中值”“请求路径均未命中”“工具执行错误”，禁止把这些情况统一折叠成模糊字符串或空对象。

#### 场景:reads 返回命中结果
- **当** 调用方向 `reads` 提交的路径中存在至少一个有效路径
- **那么** `reads` 返回成功语义
- **那么** 返回体必须包含每个请求路径对应的读取结果

#### 场景:reads 返回无命中结果
- **当** 调用方向 `reads` 提交的路径均不存在
- **那么** `reads` 返回无命中语义
- **那么** 调用方可以据此判断这是证据不足而非系统故障

#### 场景:reads 返回错误结果
- **当** `reads` 在执行过程中发生工具级异常
- **那么** `reads` 返回明确错误语义
- **那么** 调用方可以区分该失败与正常无命中

### 需求:reads 工具必须保持只读且无副作用
系统必须要求 `reads` 只读取当前状态值，而禁止写入状态、修改默认 world state、执行任务或引入其他运行期副作用。

#### 场景:planner 使用 reads 做证据确认
- **当** planner 在规划过程中调用 `reads`
- **那么** 当前 state 不得因本次调用而发生任何变化
- **那么** 返回结果只包含读取值或错误摘要

### 需求:reads 工具必须支持可手动运行的 smoke 脚本
系统必须提供一个位于 `smoke/test_reads.py` 的可手动运行脚本，用于让开发者直接观察 `reads` 的值读取、无命中和错误边界，而不是只能通过单元测试断言理解该工具行为。

#### 场景:开发者运行 reads smoke 脚本
- **当** 开发者在本地执行 `smoke/test_reads.py` 或等价命令
- **那么** 脚本会展示至少一次命中值读取结果
- **那么** 脚本会展示至少一次无命中结果
- **那么** 开发者可以从输出中看出 `reads` 的输入输出边界

### 需求:reads 工具每次调用必须使用 loguru 记录输入和输出
系统必须要求 `reads` 工具在每次调用时通过 `loguru` 记录调用输入、输出状态和错误信息，禁止把这类运行期日志责任留给上层调用方临时实现。

#### 场景:reads 成功读取值
- **当** 调用方向 `reads` 提交有效路径且工具成功返回值
- **那么** 系统必须记录本次调用的输入路径摘要
- **那么** 系统必须记录返回状态和命中数量等结果摘要

#### 场景:reads 无命中
- **当** 调用方向 `reads` 提交的路径均不存在且工具返回无命中语义
- **那么** 系统必须记录本次调用的输入路径摘要
- **那么** 系统必须记录无命中状态

#### 场景:reads 调用失败
- **当** `reads` 在执行过程中发生异常并返回错误语义
- **那么** 系统必须记录本次调用的输入路径摘要
- **那么** 系统必须记录错误类型和错误信息
