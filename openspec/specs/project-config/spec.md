# project-config 规范

## 目的
定义 `trpg_py` 包内长期运行配置的统一治理边界、唯一配置入口以及新增配置的接入规则。
## 需求
### 需求:系统必须将统一配置边界限定在 trpg_py 包内运行配置
系统必须将统一配置的强制治理范围限定为 `trpg_py` 包内的长期运行配置与工具默认参数，禁止把仓库根目录脚本、演示入口或测试辅助脚本一律视为统一配置的必接入对象。

#### 场景:包内模块引入新的长期默认配置
- **当** `trpg_py` 包内某个模块需要新增会影响跨运行默认行为的长期默认值
- **那么** 该默认值必须通过统一配置模型声明
- **那么** 该模块禁止继续以零散 `DEFAULT_*` 或分散环境变量作为长期配置真相

#### 场景:仓库脚本存在局部默认值
- **当** 仓库根目录脚本或演示入口需要声明仅服务于该脚本的默认参数、默认 fixture 或默认演示选择
- **那么** 系统不强制这些脚本默认值必须进入统一配置文件
- **那么** 开发者可以继续使用脚本局部默认值、fixture 文件或 CLI 参数

### 需求:系统必须允许包外脚本按需复用统一配置而非被强制绑定
系统必须允许仓库脚本在有需要时主动复用统一配置入口，但禁止把这种复用升级为所有包外脚本的强制规范要求。

#### 场景:脚本主动读取统一配置
- **当** 某个仓库脚本为了复用包内默认行为而读取统一配置入口
- **那么** 系统允许该脚本复用统一配置
- **那么** 这类实现选择不会自动把该脚本纳入统一配置的强制治理范围

### 需求:统一配置必须通过环境变量名引用敏感密钥
系统必须要求统一配置文件中的敏感 API 密钥字段使用环境变量名声明，禁止在统一配置文件中直接保存 planner 或 search 的真实 API key 值。

#### 场景:配置文件声明 planner 与 search 密钥来源
- **当** 开发者编写 `config/config.toml` 或其他项目配置文件
- **那么** planner 与 search 的密钥字段必须使用 `api_key_env`
- **那么** 配置文件中不得要求直接写入真实密钥值

### 需求:配置加载层必须解析 api_key_env
系统必须在统一配置加载阶段解析 `api_key_env` 指向的环境变量，并向配置消费方提供可直接使用的最终密钥值。

#### 场景:加载配置时解析环境变量
- **当** 配置文件中声明了 `api_key_env`
- **那么** `trpg_py.config` 必须读取对应环境变量
- **那么** 返回的配置对象对消费方表现为可直接使用的认证信息

### 需求:缺失密钥环境变量必须报出明确配置错误
系统必须在 `api_key_env` 未设置、对应环境变量不存在或值为空时返回明确错误，禁止静默降级为空值继续运行。

#### 场景:环境变量缺失
- **当** 配置文件引用了某个 `api_key_env` 但运行环境未设置该变量
- **那么** 配置加载必须失败
- **那么** 错误信息中必须能指出缺失的环境变量名

### 需求:新增包内项目级配置必须先扩展统一配置入口
系统必须要求后续任何 `trpg_py` 包内模块在引入新的项目级默认配置前，先扩展统一配置模型和统一配置文件示例，禁止新增独立配置文件、零散环境变量入口或新的长期默认常量真相。对于敏感认证信息，统一配置入口必须以环境变量名形式声明，而不是直接存储密钥值。

#### 场景:未来包内模块新增项目级默认值
- **当** 某个新的 `trpg_py` 包内模块需要提供项目级默认配置
- **那么** 开发者必须先扩展统一配置模型与配置文件
- **那么** 模块实现必须通过统一配置入口消费该字段
- **那么** 若该字段属于敏感认证信息，则必须使用环境变量名引用方案

### 需求:系统必须提供全项目唯一运行配置源
系统必须以单一外部 TOML 文件作为全项目运行配置源，禁止继续要求不同模块各自维护独立配置文件、模块级默认配置真相或彼此无关的环境变量入口。

#### 场景:调用方从统一配置文件启动系统
- **当** 调用方按项目约定提供根目录配置文件
- **那么** 系统从该唯一配置文件读取运行配置
- **那么** planner、search 等模块共享同一份配置真相

### 需求:系统必须提供统一配置加载入口与类型化校验
系统必须提供集中配置加载入口，并将外部 TOML 解析为类型化配置对象。系统禁止要求业务模块自行解析原始 TOML 字典或重复实现字段校验逻辑。

#### 场景:统一入口返回类型化配置对象
- **当** 调用方请求加载项目配置
- **那么** 系统返回经校验的类型化配置对象
- **那么** 下游模块可以直接消费已验证字段而无需重复转换

### 需求:配置非法或缺失时系统必须快速失败
系统在配置文件缺失、格式非法或关键字段缺失时必须返回明确错误，禁止静默回退到隐藏默认值继续运行。

#### 场景:配置文件缺失时失败
- **当** 系统启动时找不到约定的配置文件
- **那么** 系统返回明确错误
- **那么** 错误信息指出缺失的配置文件位置或名称

#### 场景:关键字段非法时失败
- **当** 配置文件中的字段类型或内容不符合要求
- **那么** 系统返回明确校验错误
- **那么** 业务模块不得带着无效配置继续运行

### 需求:系统必须将项目级默认行为统一纳入单一配置模型
系统必须将运行配置、工具默认参数、demo 入口默认行为和脚本默认输入来源统一纳入同一份项目配置模型与同一份 TOML 文件，禁止继续让这些长期默认行为分散在脚本或模块常量中。planner smoke 的默认 world state 文件路径属于可影响跨运行默认行为的脚本输入来源，也必须进入统一配置。

#### 场景:剩余脚本默认行为纳入统一配置
- **当** 系统需要为 demo runner 或 smoke script 提供默认参数
- **那么** 这些默认参数通过统一项目配置声明
- **那么** 调用方可以通过统一配置入口查看和覆写它们

#### 场景:planner smoke 默认状态来源纳入统一配置
- **当** planner smoke 脚本需要确定默认 world state 文件
- **那么** 系统必须通过统一配置提供该文件路径
- **那么** 脚本不得继续依赖硬编码的内联 demo state 作为唯一默认真相

### 需求:系统必须明确区分项目级配置与静态夹具数据
系统必须定义稳定边界来区分“项目级默认行为配置”和“静态 fixture / 领域常量”。凡是会影响跨运行默认行为的长期默认值必须进入统一配置；只属于固定示例数据、协议常量或领域常量的值禁止被强制迁移为配置。作为 smoke 默认输入来源的 world state 文件路径属于项目级配置；world state 文件内容本身则属于可维护的静态示例数据。

#### 场景:默认 world state 路径被视为项目配置
- **当** 开发者需要替换 planner smoke 默认 world state 文件
- **那么** 该文件路径必须通过统一配置声明
- **那么** 调用方无需修改脚本代码即可切换默认状态来源

#### 场景:world state 内容本体不被误判为配置字段海洋
- **当** 系统维护一份默认 `world_state.toml` 示例文件
- **那么** 统一配置文件只需要声明该文件路径
- **那么** 不必把整份世界状态本体内联塞进 `config/config.toml`

### 需求:新增项目级配置必须先扩展统一配置入口
系统必须要求后续任何模块在引入新的项目级默认配置前，先扩展统一配置模型和统一配置文件示例，禁止新增独立 `DEFAULT_*`、独立配置文件或零散环境变量入口作为长期配置真相。新增的 prompt 目录、模板文件或其他长期默认资源定位同样属于项目级配置，必须先进入统一配置入口。

#### 场景:新增模块引入项目级默认值
- **当** 某个模块需要新增项目级默认配置
- **那么** 开发者先扩展统一配置模型与统一配置文件
- **那么** 该模块通过统一配置入口消费新字段

#### 场景:新增 prompt 资源定位
- **当** planner 或其他包内模块需要新增可切换的默认 prompt/模板资源
- **那么** 开发者必须先扩展统一配置模型与配置文件示例
- **那么** 模块实现不得绕过统一配置直接硬编码新目录或文件路径

### 需求:统一配置必须声明 planner prompt 资源定位
系统必须通过统一项目配置声明 planner prompt 目录和默认模板文件，禁止让 planner prompt 的长期默认路径继续隐藏在代码常量、模块内联字符串或工作目录约定中。

#### 场景:配置文件声明 planner prompt 目录与模板
- **当** 开发者维护 `config/config.toml`
- **那么** 配置中必须可以声明 planner prompt 目录
- **那么** 配置中必须可以声明 system prompt 与 user prompt 的默认模板文件

#### 场景:相对路径相对于配置文件解析
- **当** planner prompt 目录或模板文件使用相对路径
- **那么** 系统必须相对于统一配置文件位置解析这些路径
- **那么** 调用方不必依赖当前工作目录保持一致

### 需求:统一配置必须声明 planner smoke 默认 world state 文件
系统必须允许统一项目配置声明 planner smoke 使用的默认 world state 文件路径，禁止让默认 smoke state 长期隐藏在 `smoke/test_planner.py` 的代码常量中。

#### 场景:配置文件声明 smoke world state 路径
- **当** 开发者维护 `config/config.toml`
- **那么** 配置中必须可以声明 planner smoke 默认 world state 文件路径
- **那么** 调用方可以通过统一配置入口查看或覆写该默认状态来源

#### 场景:world state 路径按配置文件位置解析
- **当** world state 文件路径使用相对路径
- **那么** 系统必须相对于统一配置文件位置解析该路径
- **那么** 脚本行为不得依赖当前工作目录
