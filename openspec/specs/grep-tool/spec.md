# grep-tool 规范

## 目的
定义面向 agent 的状态内容 grep 工具，使 planner 和其他调用方可以基于布尔表达式从当前 state 的扁平化内容行中筛出真实存在的文本事实，并在命中、无命中与错误之间保持稳定、可操作的结构化语义。

## 需求
### 需求: grep 工具必须驻留在 agent.tools 命名空间
系统必须在 `trpg_py.agent.tools` 命名空间下提供名为 `grep` 的状态路径检索工具能力，并且该能力必须可以被 Python 调用方直接导入和使用，而不是仅作为 planner 内部私有辅助逻辑存在。

#### 场景:调用方从 agent.tools 使用 grep
- **当** 开发者为 planner 或其他 agent 组装工具集
- **那么** 可以从 `trpg_py.agent.tools` 访问 `grep` 工具实现
- **那么** 调用方无需自行遍历全部 state 路径来做模糊筛选

### 需求: grep 工具必须基于扁平化状态行执行匹配
系统必须让 `grep` 先把当前 state 展平成形如 `a.b.c = data` 的文本行，再基于这些扁平化行执行匹配；禁止仅在叶子路径名层面做模糊检索后就把结果视为完整 grep 命中。

#### 场景:grep 返回扁平化状态行
- **当** 调用方向 `grep` 提交有效关键词请求
- **那么** 工具必须先把当前 state 转换为 `a.b.c = data` 形式的文本行集合
- **那么** 返回结果中的每条命中都必须对应真实存在于当前 state 快照中的扁平化行

### 需求: grep 工具必须支持批量关键词输入
系统必须允许调用方在一次 `grep` 调用中提交多个布尔表达式字符串，禁止要求调用方只能通过多次工具调用才能表达多个独立主题的筛选需求。

#### 场景:调用方一次提交多个表达式
- **当** 调用方向 `grep` 一次提交多个布尔表达式字符串
- **那么** 工具必须在同一次调用中处理所有请求
- **那么** 返回结果必须覆盖所有请求的命中并保持稳定结构化语义

### 需求: grep 工具必须支持 and 与 or 的布尔组合
系统必须让每个关键词表达式字符串支持由 `&&` 与 `||` 组成并可使用括号嵌套的布尔条件；布尔表达式必须在单条扁平化行上求值并决定该行是否命中。

#### 场景:单个布尔表达式中同时使用 and 和 or
- **当** 调用方向 `grep` 提交一个同时包含 `&&` 与 `||` 的关键词条件表达式
- **那么** 工具必须按表达式结构在单条扁平化行上求值
- **那么** 只有求值结果为真的扁平化行才能出现在命中结果中

#### 场景:嵌套表达式正确保留子条件边界
- **当** 调用方向 `grep` 提交包含嵌套子条件的关键词表达式
- **那么** 工具不得把该表达式错误降级为单一全局 `&&` 或单一全局 `||`
- **那么** 返回结果必须符合原始布尔组合语义

### 需求: grep 工具必须显式区分命中、无命中和错误
系统必须通过稳定的结构化语义区分 `grep` 的命中、无命中和执行错误，禁止把“没有相关路径”和“工具故障”折叠为同一种模糊结果。

#### 场景:grep 返回命中结果
- **当** 调用方向 `grep` 提交有效表达式且当前 state 中存在相关内容行
- **那么** `grep` 返回 `status=ok`
- **那么** 返回体包含一个或多个命中的内容行

#### 场景:grep 返回无命中结果
- **当** 调用方向 `grep` 提交有效表达式但当前 state 中不存在足够相关的内容行
- **那么** `grep` 返回 `status=no_match`
- **那么** 调用方可以据此判断这是状态发现证据不足而不是系统故障

#### 场景:grep 返回错误结果
- **当** `grep` 在执行过程中发生工具级异常
- **那么** `grep` 返回 `status=error`
- **那么** 调用方可以区分该失败与正常无命中

### 需求: grep 工具必须返回所有命中的扁平化行
系统必须让 `grep` 返回所有命中的扁平化状态行，而不是仅返回少量“最相关候选路径”；如果调用方显式提供数量上限，工具也必须把截断解释为结果限制，而不是改变“返回命中行”的语义本质。

#### 场景:grep 返回全部命中行
- **当** 当前 state 中存在多条满足关键词请求的扁平化行
- **那么** `grep` 返回结果必须包含所有命中的扁平化行
- **那么** 返回体不得把“路径候选 top-N”伪装成完整 grep 结果

### 需求: grep 工具返回项必须只包含命中的内容行
系统必须让 `grep` 的返回项只包含命中的扁平化内容行文本，禁止返回额外的标签、命中关键词、原因解释或等价的冗余元数据。

#### 场景:调用方获取命中内容
- **当** `grep` 返回一条或多条命中的扁平化行
- **那么** 每条结果必须是可直接消费的内容行文本
- **那么** 返回体不得包含标签、命中关键词或原因解释字段

### 需求: grep 返回语义必须可直接驱动 planner 上下文收集
系统必须保证 `grep` 的返回结果足够稳定，使 planner 或其他 agent 可以直接把命中的扁平化行用作半结构化上下文收集输入，而不是必须先额外推断这些命中对应的文本事实。

#### 场景:intent 节点直接消费 grep 命中行
- **当** planner 的 Intent 节点调用 `grep` 获取状态事实
- **那么** 节点必须可以直接把命中的扁平化行收集为上下文片段
- **那么** 调用方无需先把路径候选再二次转换成可读事实文本

### 需求: grep 工具每次调用必须使用 loguru 记录输入和输出
系统必须要求 `grep` 工具在每次调用时通过 `loguru` 记录调用输入、输出状态和错误信息，禁止把这类运行期日志责任留给上层调用方临时实现。

#### 场景:grep 成功返回候选
- **当** 调用方向 `grep` 提交有效关键词且工具返回 `status=ok`
- **那么** 系统必须记录本次调用的关键词摘要
- **那么** 系统必须记录返回状态以及候选数量等结果摘要

#### 场景:grep 无命中
- **当** 调用方向 `grep` 提交有效关键词且工具返回 `status=no_match`
- **那么** 系统必须记录本次调用的关键词摘要
- **那么** 系统必须记录无命中状态

#### 场景:grep 调用失败
- **当** `grep` 在执行过程中发生异常并返回错误语义
- **那么** 系统必须记录本次调用的关键词摘要
- **那么** 系统必须记录错误类型和错误信息

### 需求: grep 工具必须提供可手动运行的 smoke 脚本
系统必须提供一个位于 `smoke/test_grep.py` 的可手动运行脚本，用于让开发者直接观察 `grep` 的路径检索、无命中和错误边界，而不是只能通过单元测试断言理解其行为。

#### 场景:开发者运行 grep smoke 脚本
- **当** 开发者在本地执行 `smoke/test_grep.py` 或等价命令
- **那么** 脚本会展示至少一次关键词命中结果
- **那么** 脚本会展示至少一次无命中结果
- **那么** 开发者可以从输出中看出 `grep` 的输入输出边界
