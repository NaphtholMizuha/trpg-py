## 需求
### 需求:ask 触发决策必须由模型自主产生
系统必须要求 agent 是否发起 `ask`、发起多少次 `ask`、以及每次 ask 的问题内容由模型根据当前证据缺口自主决定。系统禁止宿主代码继续通过固定分支直接规定“缺少执行者就 ask”“目标不唯一就 ask”或其他与具体字段绑定的 ask 触发条件。

#### 场景:模型判断需要目标澄清
- **当** agent 基于当前意图、状态证据和规则证据判断目标仍无法安全落地
- **那么** agent 可以主动生成结构化 ask 请求
- **那么** ask 的问题文本、选项和默认值必须来自该次模型推理结果
- **那么** 宿主代码不得绕过模型直接构造一个预定义的目标澄清 ask

#### 场景:模型判断当前无需 ask
- **当** agent 已经能够基于现有证据继续完成上下文收集或返回阻塞结果
- **那么** agent 可以选择不发起 ask
- **那么** 宿主代码不得仅因命中特定字段缺失分支就强制插入 ask

### 需求:宿主代码必须只负责 ask 协议与恢复而不负责 ask 策略
系统必须将宿主代码对 `ask` 的职责限制为工具契约校验、interrupt/resume 承载、展示和回答回填。系统禁止在宿主代码中保留任何按 actor、target、position、spell 类型或其他业务字段分类的 ask 策略分支。

#### 场景:Context Agent 触发 ask interrupt
- **当** agent 输出一个结构化 ask 请求并调用 `ask` 工具
- **那么** 运行时负责把该调用表示为 pending interrupt
- **那么** 宿主负责展示问题并在恢复后回填结构化回答
- **那么** 宿主不得再额外执行独立的业务判断来决定是否改问另一个预定义问题
