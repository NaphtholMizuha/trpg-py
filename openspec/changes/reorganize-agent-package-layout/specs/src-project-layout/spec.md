## 新增需求

### 需求:agent 包内模块必须按核心入口与辅助实现分层收纳
系统必须将 `src/augury/agent/` 包内文件按核心入口、共享模型、子 agent、工具和辅助实现分层组织。系统禁止继续让 eval helper、CLI helper、状态加载器与其他支持性模块长期平铺在 `agent` 包根并与核心入口共享同等结构地位。

#### 场景:维护者查看 agent 包目录
- **当** 维护者查看 `src/augury/agent/` 目录
- **那么** 包根必须优先保留少量核心入口文件与稳定子目录
- **那么** 支持性 helper 必须收纳到 `agent/utils/` 或等价的辅助目录
- **那么** 维护者不需要先逐个打开文件才能判断它属于公共入口还是辅助实现

#### 场景:维护者新增一个 agent 辅助模块
- **当** 维护者新增 CLI、eval、state loading 或其他支持性 helper
- **那么** 新文件必须创建在 `agent/utils/` 或等价辅助目录
- **那么** 系统不得鼓励继续把这类模块直接平铺在 `src/augury/agent/` 包根

## 修改需求

### 需求: 运行时代码必须以 augury 作为唯一长期包命名空间
系统必须将正式运行时代码组织在 `src/augury/` 下，并以 `augury` 作为唯一长期公共导入命名空间。对于 `augury.agent` 包，系统必须进一步要求主编排入口、共享模型和辅助实现使用可辨识的包内分层；系统禁止继续把历史平铺布局保留为新的长期规范入口。

#### 场景:调用方导入正式运行时代码
- **当** 调用方需要访问公共运行时 API 或内部命名空间
- **那么** 导入路径指向 `augury`、`augury.engine`、`augury.agent` 或 `augury.store`
- **那么** 系统不得要求新代码继续以 `trpg_py` 作为长期导入前缀

#### 场景:维护者查看 agent 包内部布局
- **当** 维护者查看 `src/augury/agent/` 目录结构
- **那么** 主编排入口必须以语义清晰的模块名存在
- **那么** `models.py` 可以作为共享数据契约留在包根
- **那么** 其他支持性 helper 不得继续与主入口和模型模块长期平铺
