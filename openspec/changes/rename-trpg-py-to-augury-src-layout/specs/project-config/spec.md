## 修改需求

### 需求:系统必须将统一配置边界限定在 trpg_py 包内运行配置
系统必须将统一配置的强制治理范围限定为 `augury` 包内的长期运行配置与工具默认参数，禁止把 `src/smoke/` 下的脚本入口或其他包外验证文件一律视为统一配置的必接入对象。

#### 场景:包内模块引入新的长期默认配置
- **当** `augury` 包内某个模块需要新增会影响跨运行默认行为的长期默认值
- **那么** 该默认值必须通过统一配置模型声明
- **那么** 该模块禁止继续以零散 `DEFAULT_*` 或分散环境变量作为长期配置真相

#### 场景:仓库脚本存在局部默认值
- **当** `src/smoke/` 下的演示入口需要声明仅服务于该脚本的默认参数、默认 fixture 或默认演示选择
- **那么** 系统不强制这些脚本默认值必须进入统一配置文件
- **那么** 开发者可以继续使用脚本局部默认值、fixture 文件或 CLI 参数

### 需求:新增包内项目级配置必须先扩展统一配置入口
系统必须要求后续任何 `augury` 包内模块在引入新的项目级默认配置前，先扩展统一配置模型和统一配置文件示例，禁止新增独立配置文件、零散环境变量入口或新的长期默认常量真相。对于敏感认证信息，统一配置入口必须以环境变量名形式声明，而不是直接存储密钥值。

#### 场景:未来包内模块新增项目级默认值
- **当** 某个新的 `augury` 包内模块需要提供项目级默认配置
- **那么** 开发者必须先扩展统一配置模型与配置文件
- **那么** 模块实现必须通过统一配置入口消费该字段
- **那么** 若该字段属于敏感认证信息，则必须使用环境变量名引用方案

### 需求:统一配置必须声明 planner smoke 默认 world state 文件
系统必须允许统一项目配置声明 `src/smoke/test_planner.py` 使用的默认 world state 文件路径，禁止让默认 smoke state 长期隐藏在该脚本的代码常量中。

#### 场景:配置文件声明 smoke world state 路径
- **当** 开发者维护 `config/config.toml`
- **那么** 配置中必须可以声明 planner smoke 默认 world state 文件路径
- **那么** 调用方可以通过统一配置入口查看或覆写该默认状态来源

#### 场景:world state 路径按配置文件位置解析
- **当** world state 文件路径使用相对路径
- **那么** 系统必须相对于统一配置文件位置解析这些路径
- **那么** `src/smoke/test_planner.py` 与相关调用方不必依赖当前工作目录保持一致
