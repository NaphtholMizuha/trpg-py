## 修改需求

### 需求:系统必须将手动集成测试脚本集中放入 smoke 目录
系统必须将仓库中供开发者手动运行的集成测试脚本集中放入 `src/smoke/` 目录，禁止继续将这类脚本长期散落在仓库根目录或其他与自动测试混杂的位置。

#### 场景:新增手动集成脚本
- **当** 开发者需要新增一个可手动运行的 engine、tool 或 planner 验证脚本
- **那么** 该脚本必须创建在 `src/smoke/` 目录下
- **那么** 该脚本不得作为根目录长期入口存在

### 需求:系统必须将根目录 test 前缀脚本迁移出根目录
系统必须将仓库根目录下历史遗留的手动集成脚本迁移到 `src/smoke/`，并将自动测试迁移到 `src/tests/`，禁止在完成迁移后继续同时维护根目录与 `src/` 目录两套长期入口。

#### 场景:收敛现有根目录手动脚本
- **当** 仓库中存在历史遗留的手动运行脚本或自动测试目录
- **那么** 手动集成脚本迁移到 `src/smoke/`
- **那么** 自动测试迁移到 `src/tests/`
- **那么** 系统不得继续保留等价的根目录长期脚本或测试入口

### 需求:smoke 目录必须与自动测试发现目录职责分离
系统必须将 `src/smoke/` 视为“手动执行的集成验证入口”目录，将 `src/tests/` 视为自动测试套件目录，禁止将两者职责混淆。

#### 场景:开发者区分手动脚本与自动测试
- **当** 开发者查看 `src/smoke/` 与 `src/tests/` 两个目录
- **那么** 可以明确区分前者用于手动运行验证，后者用于自动测试套件
- **那么** 手动脚本目录不会隐式替代自动测试目录语义
