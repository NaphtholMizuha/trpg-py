## 新增需求

### 需求:统一配置必须声明 planner smoke 默认 world state 文件
系统必须允许统一项目配置声明 planner smoke 使用的默认 world state 文件路径，禁止让默认 smoke state 长期隐藏在 `smoke/test_planner.py` 的代码常量中。

#### 场景:配置文件声明 smoke world state 路径
- **当** 开发者维护 `config/config.toml`
- **那么** 配置中必须可以声明 planner smoke 默认 world state 文件路径
- **那么** 调用方可以通过统一配置入口查看或覆写该默认状态来源

#### 场景:world state 路径按配置文件位置解析
- **当** world state 文件路径使用相对路径
- **那么** 系统必须相对于统一配置文件位置解析该路径
- **那么** 脚本行为不得依赖当前工作目录

## 修改需求

### 需求:系统必须将项目级默认行为统一纳入单一配置模型
系统必须将运行配置、工具默认参数、demo 入口默认行为和脚本默认输入来源统一纳入同一份项目配置模型与同一份 TOML 文件，禁止继续让这些长期默认行为分散在脚本或模块常量中。planner smoke 的默认 world state 文件路径属于可影响跨运行默认行为的脚本输入来源，也必须进入统一配置。

#### 场景:剩余脚本默认行为纳入统一配置
- **当** 系统需要为 demo runner 或 smoke script 提供默认参数
- **那么** 这些默认参数通过统一项目配置声明
- **那么** 调用方可以通过统一配置入口查看和覆写它们

#### 场景:planner smoke 默认状态来源纳入统一配置
- **当** planner smoke 脚本需要确定默认 world state 文件
- **那么** 系统必须通过统一配置提供该文件路径
- **那么** 脚本不得继续依赖硬编码的内联 demo state 作为唯一默认真相

### 需求:系统必须明确区分项目级配置与静态夹具数据
系统必须定义稳定边界来区分“项目级默认行为配置”和“静态 fixture / 领域常量”。凡是会影响跨运行默认行为的长期默认值必须进入统一配置；只属于固定示例数据、协议常量或领域常量的值禁止被强制迁移为配置。作为 smoke 默认输入来源的 world state 文件路径属于项目级配置；world state 文件内容本身则属于可维护的静态示例数据。

#### 场景:默认 world state 路径被视为项目配置
- **当** 开发者需要替换 planner smoke 默认 world state 文件
- **那么** 该文件路径必须通过统一配置声明
- **那么** 调用方无需修改脚本代码即可切换默认状态来源

#### 场景:world state 内容本体不被误判为配置字段海洋
- **当** 系统维护一份默认 `world_state.toml` 示例文件
- **那么** 统一配置文件只需要声明该文件路径
- **那么** 不必把整份世界状态本体内联塞进 `config/config.toml`
