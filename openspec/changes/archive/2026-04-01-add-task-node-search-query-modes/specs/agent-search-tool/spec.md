## 新增需求

### 需求:search 工具必须支持显式查询模式
系统必须允许调用方通过 `mode` 显式表达规则检索意图，支持 `term`、`balanced`、`semantic` 三种模式。系统禁止继续把所有规则检索都隐含视为同一种 HyDE 风格查询。

#### 场景:调用方以术语模式检索明确规则名
- **当** 调用方向 `search` 提交一个带有明确规则术语的查询，并将 `mode` 设置为 `term`
- **那么** 工具必须接受该模式并按正常检索流程返回结果
- **那么** 调用方可以将该查询理解为用于定位规则条目身份

#### 场景:调用方以平衡模式检索术语加结算细节
- **当** 调用方向 `search` 提交一个保留明确术语锚点且补充少量结算信息的查询，并将 `mode` 设置为 `balanced`
- **那么** 工具必须接受该模式并按正常检索流程返回结果
- **那么** 调用方可以将该查询理解为同时服务于规则身份定位与少量结算信息确认

#### 场景:调用方以语义模式检索规则场景
- **当** 调用方向 `search` 提交一个没有可靠术语锚点的规则场景描述，并将 `mode` 设置为 `semantic`
- **那么** 工具必须接受该模式并按正常检索流程返回结果
- **那么** 调用方可以将该查询理解为场景化规则检索，而不是明确术语定位

### 需求:search 工具必须记录查询模式以支持调试和评估
系统必须在每次 `search` 调用的日志或可观察输出中记录实际使用的 `mode`，禁止让调用方只能从 query 文本猜测本次检索意图。

#### 场景:search 成功返回命中时记录 mode
- **当** 调用方向 `search` 发起带有 `mode` 的检索并成功返回命中结果
- **那么** 系统必须记录本次调用使用的 `mode`
- **那么** 系统必须继续记录 query、limit、fetch_k 和结果摘要

#### 场景:search 无命中或失败时记录 mode
- **当** 调用方向 `search` 发起带有 `mode` 的检索且返回 `no_match` 或 `error`
- **那么** 系统必须记录本次调用使用的 `mode`
- **那么** 调试人员必须能够从日志中区分这是术语检索、平衡检索还是语义检索

## 修改需求

### 需求:search 工具必须根据 query 从 Qdrant 检索规则原文
系统必须允许调用方提供 query，并使用该 query 向 Qdrant 检索匹配的规则文本。系统返回的命中结果必须保留原始文本及必要元数据，禁止把检索结果替换为模型生成的摘要或规则推断。对于当前 `trpg_knowledge` 知识库，search 必须以 payload 中的 `text` 作为命中正文来源，并稳定暴露 `book`、`path`、`doc_type`、`title`、`parent_id`、`section_titles` 等当前 schema 字段，而不是依赖旧版 `content`、`file`、`parent_content` 等历史字段作为长期契约。search 默认认证信息必须通过统一配置解析后的环境变量密钥获取，而不是要求调用方把密钥直接写入项目配置文件。search 还必须允许调用方显式提供查询模式，以表达这次检索更偏向术语定位、术语加结算信息，还是纯规则场景。

#### 场景:search 返回匹配原文
- **当** 调用方向 search 工具提交一个有效 query
- **那么** 工具会向 Qdrant 发起检索
- **那么** 返回结果中的每条命中都包含匹配原文
- **那么** 返回结果可以包含诸如标题、定位信息、分数等必要元数据
- **那么** 返回结果不得伪装成规则事实提取或 `TaskDocument` 建议
- **那么** 默认配置路径不得要求调用方在配置文件中直接保存真实密钥

#### 场景:search 返回当前知识库的稳定来源字段
- **当** `search` 命中了当前 `trpg_knowledge` 集合中的节点
- **那么** 每条命中的正文必须来自 payload 的 `text`
- **那么** 每条命中的元数据必须可以稳定提供 `book`、`path`、`doc_type`、`title`
- **那么** 每条命中的元数据必须在存在时保留 `parent_id` 和 `section_titles`
- **那么** 调用方不得被迫依赖 `file`、`type`、`parent_content` 等历史键名来理解命中来源

#### 场景:search 接受显式查询模式
- **当** 调用方向 `search` 提交一个有效 query 并附带 `mode`
- **那么** 工具必须接受该 `mode` 并继续返回同样稳定的原文和元数据字段
- **那么** 调用方不得为了表达检索意图而创建额外的并行 search 工具
