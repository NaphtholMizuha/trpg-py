## 为什么

当前 agent 在调用 `search`、`fetch_keys` 等工具时，调用方只能通过最终结果推测中间发生了什么，缺少一条稳定的运行期日志来观察每次工具调用的输入、输出和失败情况。这样一来，排查 planner 黑盒、工具参数错误或外部依赖异常时都比较费劲。

现在需要把工具调用日志下沉到工具层，并统一使用 `loguru` 记录输入和输出，让每次 agent 使用工具时都留下可追踪的日志证据，而不是只依赖 smoke 摘要或测试断言。

## 变更内容

- 为现有 agent 工具调用增加统一的 `loguru` 日志记录，覆盖调用输入、输出状态和错误结果。
- 规定 planner 所依赖的工具在被 agent 调用时必须产生日志，而不是只在调用方脚本里临时打印。
- 为工具日志补充测试，确保正常结果、无命中和错误分支都能留下可读日志。
- 视需要补充 smoke/debug 文档或脚本说明，帮助开发者在手动调试时查看这些日志。

## 功能 (Capabilities)

### 新增功能

### 修改功能
- `agent-planner`: planner 使用的工具链路需要提供稳定的调用日志，便于排查规划过程中的工具输入输出。
- `agent-search-tool`: search 工具在每次调用时需要记录输入、输出状态和错误信息。
- `fetch-keys-tool`: fetch_keys 工具在每次调用时需要记录输入、输出状态和错误信息。

## 影响

- `trpg_py/agent/tools/search.py` 与 `trpg_py/agent/tools/fetch_keys.py` 的工具调用路径
- `trpg_py/agent/planner.py` 的调试与排障体验
- 与工具调用相关的测试覆盖和日志断言
- 运行期日志输出内容与开发者调试方式
