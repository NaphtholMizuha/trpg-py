## 为什么

当前解析器已经具备基础执行能力，但针对规则边界的自动化测试还不够完整。像攻击天然 20/天然 1、优势与劣势的不同组合、范围查找过滤、资源不足失败回滚，以及治疗不超过生命上限这类行为都属于高回归风险点，值得被固定为明确的回归用例。同时，`main.py` 现在承担了“给人看结果”的入口角色，也需要有集成测试来证明展示内容足够清楚、足够可信。

## 变更内容

- 扩充针对检定类步骤的确定性测试，覆盖攻击大成功、大失败、优势、劣势以及优势与劣势相互抵消。
- 扩充针对操作类步骤的回归测试，覆盖范围查询过滤、资源不足时状态不变，以及治疗写回时的生命上限封顶。
- 为 `main.py` 增加面向人类可读输出的集成测试，验证关键示例会展示任务状态、步骤结果和状态变更，让读者能理解“发生了什么”和“为什么可信”。
- 明确 `heal.apply` 在能够解析到目标生命上限时的行为约束，避免治疗把生命值写到上限之上。

## 功能 (Capabilities)

### 新增功能

- 无

### 修改功能

- `dnd5e-combat-operations`: 明确治疗结算在可解析到目标生命上限时必须封顶，并补充用于驱动回归测试的场景。

## 影响

- `trpg_py/operations.py` 中 `heal.apply` 的结算逻辑
- `tests/test_checks.py` 与 `tests/test_operations.py` 的测试覆盖范围
- `main.py` 的摘要输出与对应的集成测试
- 可能新增专门的测试任务文档或夹具，以便稳定覆盖边界行为
