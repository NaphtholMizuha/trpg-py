## 新增需求

### 需求:lint 工具必须驻留在 agent.tools 命名空间
系统必须在 `trpg_py.agent.tools` 命名空间下提供名为 `lint` 的工具能力，并且该能力必须可以被 Python 调用方直接导入和使用，而不是仅作为 planner 内部私有辅助函数存在。

#### 场景:调用方从 agent.tools 使用 lint
- **当** 开发者为 planner 或其他 agent 组装工具集
- **那么** 可以从 `trpg_py.agent.tools` 访问 `lint` 工具实现
- **那么** 调用方不需要自行拼装任务文档校验逻辑

### 需求:lint 工具必须复用现有 TaskDocument 校验链路
系统必须让 `lint` 工具复用现有 `TaskDocument` Schema 和执行器语义校验逻辑，禁止维护一套与最终守门结果不一致的独立合法性规则。

#### 场景:lint 与最终守门结果保持一致
- **当** 调用方向 `lint` 提交一个候选 `TaskDocument`
- **那么** `lint` 必须基于与最终 planner/执行器一致的结构和语义校验链路给出结论
- **那么** 调用方可以将 `lint` 结果视为最终守门前的一致性预检

### 需求:lint 工具必须显式区分合法、非法和错误
系统必须通过稳定的结构化语义区分候选文档合法、候选文档非法和工具执行错误，禁止把字段错误、语义错误和系统故障折叠成同一种模糊字符串结果。

#### 场景:lint 返回合法结果
- **当** 调用方向 `lint` 提交一个满足 Schema 与执行器语义约束的候选 `TaskDocument`
- **那么** `lint` 返回合法语义
- **那么** 返回体可以明确表明该候选文档通过校验

#### 场景:lint 返回非法结果
- **当** 调用方向 `lint` 提交一个缺少步骤字段或违反执行器语义的候选 `TaskDocument`
- **那么** `lint` 返回非法语义
- **那么** 返回体必须包含可供调用方定位问题的结构化错误信息

#### 场景:lint 返回工具错误
- **当** `lint` 在处理过程中发生非候选文档本身导致的异常
- **那么** `lint` 返回明确错误语义
- **那么** 调用方可以区分这是工具故障而不是文档非法

### 需求:lint 工具必须保持只读且无副作用
系统必须要求 `lint` 只执行候选 `TaskDocument` 校验，而禁止执行任务、写入 state、消耗资源或引入其他运行期副作用。

#### 场景:planner 用 lint 做预检
- **当** planner 在规划过程中调用 `lint`
- **那么** `lint` 只返回候选文档的合法性结论和错误详情
- **那么** 当前 state、资源和执行结果不得因本次调用而发生变化

### 需求:lint 返回结果必须可直接驱动 planner 修复分支
系统必须保证 `lint` 返回结果足够结构化，使 planner 可以根据字段定位和错误摘要修复候选文档，而不是只能消费一段不可分解的大文本报错。

#### 场景:planner 根据 lint 错误修复步骤字段
- **当** `lint` 发现某个步骤缺少 `id`、`type`、`kind` 或 `args`
- **那么** 返回结果中必须能定位到对应字段路径
- **那么** planner 可以据此补齐候选文档后再次校验
