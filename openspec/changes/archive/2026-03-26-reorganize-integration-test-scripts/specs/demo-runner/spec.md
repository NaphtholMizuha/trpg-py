## 修改需求

### 需求:Demo 运行器必须支持单案例运行
系统必须允许调用方通过 `smoke/test_engine.py <demo-name>` 运行单个已注册 demo 案例。每个 demo 必须关联确定性的任务文档、初始状态和固定骰子来源，以保证输出可复现。

#### 场景:运行单个演示案例
- **当** 调用方执行 `python -B smoke/test_engine.py fireball`
- **那么** 系统运行名为 `fireball` 的 demo
- **那么** 输出中包含任务名、步骤摘要和已应用的状态变更

### 需求:Demo 运行器必须支持批量运行全部案例
系统必须允许调用方通过一个显式的批量入口一次运行全部已注册 demo 案例。批量运行必须使用稳定顺序逐个执行案例，并为每个案例输出独立摘要区块。

#### 场景:批量运行全部案例
- **当** 调用方执行 `python -B smoke/test_engine.py all`
- **那么** 系统按稳定顺序运行全部已注册 demo
- **那么** 输出中包含每个 demo 的独立摘要区块
- **那么** 输出结尾包含整体汇总状态

### 需求:Demo 仓库脚本入口不必须接入统一项目配置
系统必须允许 `smoke/test_engine.py` 这类仓库脚本入口继续以脚本局部默认值、注册表默认行为或 CLI 参数运行 demo，禁止把统一项目配置当作该脚本入口的强制前置条件。

#### 场景:开发者直接运行 demo 脚本
- **当** 开发者执行 `python -B smoke/test_engine.py fireball` 或其他 demo 命令
- **那么** 系统可以在不依赖统一项目配置的前提下运行对应 demo
- **那么** 调用方仍然可以通过显式参数或脚本内约定得到稳定结果
