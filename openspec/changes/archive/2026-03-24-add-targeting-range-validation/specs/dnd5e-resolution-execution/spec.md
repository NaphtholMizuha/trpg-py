## 新增需求

### 需求:任务文档必须允许选择步骤显式声明 targeting 输入
系统必须允许选择步骤在 `args.targeting` 中显式声明目标选取距离校验输入。该结构至少必须支持 `source_position`、`max_range` 和 `range_metric`，并且必须作为可校验字段参与任务文档验证。

#### 场景:任务文档声明单体目标距离校验
- **当** 调用方定义一个 `select.target` 步骤
- **当** 该步骤在 `args.targeting` 中提供 source 位置与最大距离
- **那么** 系统接受该任务结构进入后续校验
- **那么** 执行阶段可据此完成目标距离判定

### 需求:执行报告必须体现选择步骤的超距失败
系统必须在标准化执行报告中明确记录选择步骤因超距而失败的状态与原因。系统不得将超距失败仅表现为无目标结果，也不得与 `skipped` 或合法空结果混淆。

#### 场景:执行报告记录目标超距
- **当** 一个 `select.target` 步骤因目标超距而失败
- **那么** 该步骤在执行报告中的状态为 `failed`
- **那么** 该步骤在执行报告中包含可读的失败原因

## 修改需求

### 需求:任务文档必须允许步骤显式声明依赖字段路径
系统必须允许步骤在 `args` 中显式声明其依赖的状态字段路径或路径模板，用于读取或写回战斗状态。系统不得要求所有计算都依赖固定的默认字段路径。对于声明了 `targeting` 的选择步骤，系统必须接受用于 `source_position`、`origin`、候选池和 `field_map` 的结构化输入。

#### 场景:伤害步骤显式声明生命值路径模板
- **当** 调用方定义一个伤害步骤
- **当** 该步骤提供 `target_hp_path_template`
- **那么** 系统接受该步骤结构
- **那么** 后续执行阶段按该模板定位目标生命值字段

#### 场景:范围选择步骤显式声明 targeting 与 origin
- **当** 调用方定义一个 `select.area` 步骤
- **当** 该步骤提供 `origin` 和 `args.targeting.source_position`
- **那么** 系统接受该步骤结构
- **那么** 后续执行阶段可据此判定选点是否超距

### 需求:执行器必须返回标准化执行报告
系统必须返回包含任务状态、每个步骤执行状态、步骤输出、已提交状态变更、跳过信息、错误信息与事件列表的执行报告，以便测试和上层系统消费。若选择步骤因目标选取距离校验失败，报告必须把该失败与空 `target_ids` 成功结果明确区分。

#### 场景:运行时失败会在报告中保留已执行信息
- **当** 前两个步骤已成功提交状态变更
- **当** 第三个步骤因无效路径写入而失败
- **那么** 系统停止后续步骤执行
- **那么** 返回结果中包含前两个步骤的输出与已提交变更
- **那么** 返回结果中包含第三个步骤的失败原因

#### 场景:超距失败不会伪装成空目标结果
- **当** 一个 `select.area` 步骤因 source 到 origin 超距而失败
- **那么** 返回结果中该步骤状态为 `failed`
- **那么** 返回结果中不得仅以 `target_ids=[]` 代表该失败
