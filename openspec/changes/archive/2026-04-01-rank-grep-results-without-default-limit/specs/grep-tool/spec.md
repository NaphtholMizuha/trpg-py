## 修改需求

### 需求:grep 工具必须返回所有命中的结构化结果
系统必须让 `grep` 返回所有命中的结构化结果，而不是仅返回少量“最相关候选路径”或单个整行字符串；如果调用方显式提供数量上限，工具也必须把截断解释为对排序后结果的限制，而不是改变“返回命中结果”的语义本质。

#### 场景:grep 返回全部命中结果
- **当** 当前 state 中存在多条满足关键词请求的扁平化状态行
- **那么** `grep` 返回结果必须先基于完整命中集合形成排序结果
- **那么** 返回体不得把“扫描到前 N 条就停止”伪装成完整 grep 结果
- **那么** 每条命中必须至少包含 `key`、`value` 和 `sim`

#### 场景:调用方显式传入 limit
- **当** 调用方向 `grep` 显式传入 `limit`
- **那么** 工具必须先完成命中收集和相关性排序
- **那么** 只在排序完成后对结果做截断

### 需求:grep 工具返回语义必须可直接驱动 planner 上下文收集
系统必须保证 `grep` 的返回结果足够稳定，使 planner 或其他 agent 可以直接把命中的结构化结果用作半结构化上下文收集输入，而不是必须先额外推断这些命中对应的文本事实。

#### 场景:intent 节点直接消费 grep 命中结果
- **当** planner 的 Intent 节点调用 `grep` 获取状态事实
- **那么** 节点必须可以直接消费 `key` 与 `value` 来形成上下文片段
- **那么** 节点必须可以读取 `sim` 观察排序相对强度
- **那么** 命中结果必须按相关性优先顺序排列
- **那么** 调用方无需依赖状态枚举顺序来获得更有用的前几条事实

### 需求:grep 工具必须支持相关性排序
系统必须要求 `grep` 对所有命中的扁平化状态行进行相关性排序，禁止继续仅按展平状态的自然枚举顺序返回结果。

#### 场景:高噪音实体查询
- **当** 调用方向 `grep` 提交会命中大量行的实体查询
- **那么** 与查询表达式更直接相关的命中必须排在前面
- **那么** 结果顺序不得仅由 state 的展平顺序决定

#### 场景:同分结果保持稳定顺序
- **当** 两条或多条命中的相关性得分相同
- **那么** `grep` 必须保持稳定次序
- **那么** 相同输入不得产生不稳定的命中排列

### 需求:grep 结构化结果必须显式区分 key、value 和 sim
系统必须要求 `grep` 的每条命中都显式返回路径键、对应值和排序分数，禁止继续把这些信息压缩成单个字符串。

#### 场景:调用方读取命中详情
- **当** 调用方向 `grep` 提交有效表达式并获得命中
- **那么** 每条命中必须提供 `key`
- **那么** 每条命中必须提供 `value`
- **那么** 每条命中必须提供 `sim`
