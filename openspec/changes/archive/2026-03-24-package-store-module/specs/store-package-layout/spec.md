## 新增需求

### 需求:store 逻辑必须组织为独立包
系统必须将状态存储相关代码组织到独立的 `trpg_py/store/` 包中，而不是继续依赖单一的 `trpg_py/store.py` 文件承载全部实现。

#### 场景:store 包作为公开入口
- **当** 调用方导入 `trpg_py.store`
- **那么** 系统必须从 `trpg_py/store/__init__.py` 提供稳定的公开接口入口

#### 场景:store 内部代码按职责分布
- **当** 维护者查看状态存储实现
- **那么** 与 store 相关的实现、导出和兼容辅助代码必须位于 `trpg_py/store/` 包内，而不是继续分散在单文件实现中

### 需求:公开 store 接口语义保持兼容
系统在调整文件结构后，必须继续提供 `read`、`reads`、`write`、`writes`、`mod`、`mods` 六个公开接口，并保持其现有行为与调用语义兼容。

#### 场景:调用方继续使用现有 store 接口
- **当** 调用方通过 `trpg_py.store` 访问六个公开接口
- **那么** 它们必须继续工作且不要求调用方改变参数协议

### 需求:兼容入口在重组后仍可工作
系统在将 store 重构为包后，必须继续支持现有兼容入口，除非调用方明确迁移。

#### 场景:state 兼容层继续转发
- **当** 调用方通过 `trpg_py.state` 或 `trpg_py.engine.state` 访问旧兼容函数
- **那么** 这些入口必须继续转发到新的 store 包实现，并保持现有错误语义
