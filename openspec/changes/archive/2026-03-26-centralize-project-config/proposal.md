## 为什么

当前项目的运行配置分散在多个模块内部，以 `DEFAULT_*` 常量、环境变量名和构造参数默认值的形式各自存在。这样虽然启动快，但会造成“默认值写死在代码里、配置入口不唯一、不同模块解析规则不一致”的问题，后续扩展 planner、search 或其他运行时能力时会越来越难维护。

现在推进这项变更，可以把全项目的运行配置收敛为一份统一、可审计、可迁移的外部 TOML 配置文件，并建立唯一配置读取入口，避免继续在各处复制新的配置常量。

## 变更内容

- 新增统一项目配置能力，定义唯一配置源、外部 TOML 文件格式和统一加载入口。
- 规定运行时配置必须由集中配置模块读取，禁止业务模块继续各自声明零散的默认值与环境变量解析逻辑。
- 迁移 planner factory 的模型、超时、重试、工具预算等配置，改为从统一项目配置中读取。
- 迁移 search 工具的 API、Qdrant 与检索默认参数配置，改为从统一项目配置中读取。
- **BREAKING**: 现有直接依赖环境变量或模块内 `DEFAULT_*` 常量的调用方式将收敛到统一配置文件与统一配置入口。

## 功能 (Capabilities)

### 新增功能
- `project-config`: 定义全项目唯一配置源、外部 TOML 文件格式、配置加载入口以及配置读取语义。

### 修改功能
- `agent-planner`: 将 planner factory 的默认配置与环境变量解析逻辑改为消费统一项目配置。
- `agent-search-tool`: 将 search 工具的 API、Qdrant 和检索默认配置改为消费统一项目配置。

## 影响

- 受影响代码：新增配置模块与 TOML 配置文件；修改 `trpg_py.agent.planner` 与 `trpg_py.agent.tools.search`。
- 受影响规范：新增 `specs/project-config/spec.md`；增量修改 `specs/agent-planner/spec.md` 与 `specs/agent-search-tool/spec.md`。
- 受影响测试：新增配置加载、配置优先级和配置迁移测试；调整 planner/search 相关测试。
- 受影响使用方式：调用方需要通过统一配置文件或统一配置入口管理项目配置，而不是依赖散落在代码中的默认值。
