## 为什么

当前 `grep` 工具只支持单次关键词集合输入，并且返回的是“相关叶子路径候选”，这更像路径发现器，而不是可直接供 planner 做事实筛选的文本 grep。随着 planner 重设计需要更稳定地获取半结构化上下文，调用方需要一次提交多组关键词、明确指定关键词是“与”还是“或”，并直接拿到可读的扁平化状态行。

## 变更内容

- 将 `grep` 的匹配对象从“canonical 叶子路径名”扩展为“扁平化状态行”，格式为 `a.b.c = data`。
- 允许调用方在一次 `grep` 调用中提交多组关键词输入，而不是只能提交单个 `query` 或单个 `terms` 数组。
- 为关键词匹配显式增加两种逻辑模式：`and` 与 `or`，使调用方可以控制“必须全部命中”还是“命中任一关键词即可”。
- 调整 `grep` 返回语义，使其返回所有命中的扁平化行，并保留结构化状态区分 `ok` / `no_match` / `error`。
- 更新 `grep` 的日志、测试和 smoke 行为，使批量输入与 `and`/`or` 语义可观测且可验证。

## 影响

- 受影响代码：`src/augury/agent/tools/grep.py` 及其输出 schema、日志和匹配实现。
- 受影响调用方：所有依赖 `grep` 结果结构的 planner 或其他 agent 组装逻辑。
- 受影响验证：`grep` 相关单元测试与 `src/smoke/test_grep.py` 的输入输出示例需要同步更新。
