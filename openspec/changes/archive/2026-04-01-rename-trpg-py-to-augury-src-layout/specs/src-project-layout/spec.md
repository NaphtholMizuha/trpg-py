## 新增需求

### 需求:Python 源文件必须统一收敛到 src 根
系统必须将仓库中的 Python 运行时代码、手动 smoke 脚本和自动测试统一收敛到 `src/` 根下，禁止继续把包目录、`smoke/` 或 `tests/` 长期平铺在仓库根目录。

#### 场景:维护者查看仓库顶层布局
- **当** 维护者查看重构后的仓库目录
- **那么** Python 相关源码根目录是 `src/`
- **那么** 仓库根目录不再长期保留与 `src/` 等价的 `trpg_py/`、`smoke/` 或 `tests/` 目录真相

### 需求:运行时代码必须以 augury 作为唯一长期包命名空间
系统必须将正式运行时代码组织在 `src/augury/` 下，并以 `augury` 作为唯一长期公共导入命名空间，禁止继续把 `trpg_py` 保留为新的规范入口。

#### 场景:调用方导入正式运行时代码
- **当** 调用方需要访问公共运行时 API 或内部命名空间
- **那么** 导入路径指向 `augury`、`augury.engine`、`augury.agent` 或 `augury.store`
- **那么** 系统不得要求新代码继续以 `trpg_py` 作为长期导入前缀

### 需求:手动 smoke 与自动 tests 必须在 src 下保持分层
系统必须将手动验证脚本组织在 `src/smoke/`，并将自动测试组织在 `src/tests/`，禁止把二者重新混入同一目录或重新平铺到仓库根目录。

#### 场景:维护者新增验证入口
- **当** 维护者新增一个手动 smoke 脚本或自动测试文件
- **那么** 手动脚本创建在 `src/smoke/`
- **那么** 自动测试创建在 `src/tests/`
- **那么** 维护者无需通过文件名猜测该文件属于手动验证还是自动测试
