## 新增需求

### 需求:fetch_keys 演示脚本必须从统一项目配置读取长期默认输入
系统必须要求 `fetch_keys` 的演示/测试脚本通过统一项目配置获取长期默认输入来源与默认演示参数，禁止继续把这些长期默认行为写死在脚本级常量中作为唯一真相。

#### 场景:fetch_keys 演示脚本读取统一默认输入
- **当** 开发者在不显式传参的情况下运行 `fetch_keys` 演示脚本
- **那么** 脚本从统一项目配置读取默认输入来源或默认演示参数
- **那么** 开发者可以通过统一配置调整脚本默认行为

## 修改需求

### 需求:系统必须提供可运行的 fetch_keys 演示测试脚本
系统必须提供一个可直接运行的测试脚本（例如 `test_fetch_keys.py`），用于让开发者直接观察 `store.keys` 与 `agent.tools.fetch_keys` 的核心行为，而不是仅依赖单元测试断言。该脚本的长期默认输入来源和默认演示参数必须通过统一项目配置声明。

#### 场景:开发者运行演示脚本观察 fetch_keys 功能
- **当** 开发者在本地执行该测试脚本
- **那么** 脚本会展示至少一次全量路径枚举结果
- **那么** 脚本会展示至少一次按范围枚举结果
- **那么** 开发者可以从脚本输出看出新能力的功能边界
