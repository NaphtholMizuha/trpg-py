## 为什么

上一轮 `centralize-project-config` 已经把 planner 与 search 的运行配置收敛到统一入口，但项目里仍然存在未纳入统一配置体系的默认参数和脚本级配置，例如 demo runner 的默认行为、`fetch_keys` 演示脚本中的内置默认状态，以及后续新增模块可能继续各自声明新配置。现在推进这项变更，是为了把“统一配置”从局部迁移升级为项目级规则，避免配置再次分叉回代码常量和脚本参数里。

## 变更内容

- 扩展统一项目配置能力，明确项目中的运行配置、工具默认参数、demo/脚本默认参数都必须纳入同一份配置模型与同一份 TOML 文件。
- 为 demo runner 补充统一配置约束，使 demo 入口的默认输出、示例选择或运行相关默认值不再在脚本内长期分散维护。
- 为 `fetch_keys` 的演示/测试脚本补充统一配置约束，使脚本级默认状态文件、演示输入和相关默认参数可以通过统一配置入口管理，而不是写死在脚本模块里。
- 建立新增配置的治理规则：后续任何新模块若引入项目级默认运行配置，必须先扩展统一配置模型，而不是新增独立 `DEFAULT_*`、独立配置文件或零散环境变量入口。
- **BREAKING**: 项目中剩余的脚本级和工具级长期默认配置将继续从代码常量迁移到统一配置文件；未来新增项目配置不再允许绕开统一配置入口直接落在模块内部。

## 功能 (Capabilities)

### 新增功能
- `project-config`: 定义全项目配置治理规则，覆盖运行配置、工具默认参数、demo/脚本默认参数以及新增配置的接入约束。

### 修改功能
- `demo-runner`: 将 demo runner 的长期默认配置纳入统一项目配置，而不是继续停留在脚本内部。
- `fetch-keys-tool`: 将 `fetch_keys` 相关演示脚本和工具默认参数纳入统一项目配置，并约束其默认行为来源。

## 影响

- 受影响代码：`trpg_py.config`、`main.py`、`test_fetch_keys.py`、可能新增的配置访问辅助代码及其调用路径。
- 受影响规范：新增/扩展 `specs/project-config/spec.md`，并增量修改 `specs/demo-runner/spec.md` 与 `specs/fetch-keys-tool/spec.md`。
- 受影响测试：需要新增统一配置覆盖 demo runner 与 `fetch_keys` 脚本默认行为的测试，并更新相关运行说明。
- 受影响使用方式：开发者需要把剩余脚本和 demo 默认配置也收敛到统一 TOML 中，后续新增配置必须先扩展统一配置模型。
