## 为什么

当前仓库还没有一个能够描述并执行 DnD5e 战斗判定流程的统一机制。把判定逻辑直接写死在 Python 分支里，会让伤害、豁免、资源扣减、状态结算和 buff 叠加难以复用，也难以通过配置表达复杂战斗动作。

现在引入一个以 JSON 任务为输入、以点分路径状态字典为执行目标的解析器，可以把“要做什么”与“如何执行”分开，为后续扩展技能、法术、特性和怪物动作建立统一基础。

## 变更内容

- 新增一个 DnD5e 判定解析与执行能力，能够读取描述战斗流程的任务 JSON，并按顺序执行其中的步骤。
- 新增统一的任务 JSON 结构，使用顶层 `task_id`、`version`、`policy`、`context` 和 `steps` 描述一次可执行的战斗流程。
- 新增显式字段映射能力，使任务 JSON 可以声明计算依赖的状态字段路径，而不要求状态对象固定采用某一种字段组织形式。
- 新增点分路径状态访问与更新机制，用于读取和写入战斗状态中的角色属性、资源、效果与战斗结果。
- 新增一组可组合的原子操作，覆盖常见 DnD5e 战斗流程，包括目标选择与范围查找、属性/技能检定、攻击命中判定、豁免判定、伤害结算、资源扣减、buff/debuff 添加与持续状态更新，并明确优先遵循“先选目标，再做检定，再做结算”的步骤流。
- 新增标准化的执行结果输出，记录每个步骤是否成功、产生了哪些状态变更，以及需要暴露给上层系统的日志或事件。
- 明确第一阶段范围：先支持通用执行框架与核心战斗操作，不在本次变更中实现完整法术库、职业特性全集或所有边缘规则。

## 功能 (Capabilities)

### 新增功能
- `dnd5e-resolution-execution`: 定义如何解析任务 JSON、按顺序执行步骤、读取上下文并将结果写回点分路径状态，以及如何在步骤之间传递目标集合。
- `dnd5e-combat-operations`: 定义用于 DnD5e 战斗流程的原子操作集合及其行为约束，包括目标选择、范围查找、判定、伤害、资源和状态效果处理。

## 影响

- 受影响代码：将新增解析器、执行器、状态访问器、原子操作模块及对应测试。
- API 影响：形成一套面向 JSON 任务输入和状态字典输出的内部执行接口。
- 数据影响：需要约定任务 JSON 结构、步骤字段约定、执行上下文格式、点分路径状态模型、用于范围查找的目标与位置信息，以及 `field_map` / 显式路径模板的写法。
- 系统影响：为后续更高层的技能、法术、AI 动作生成与战斗回放提供可复用基础。
