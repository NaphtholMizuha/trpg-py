## 为什么

当前项目把真实或占位 API key 直接放在 `config/config.toml` 的 `api_key` 字段里，这会把敏感信息配置和普通运行配置混在一起，既不安全，也不利于多人协作和配置分发。统一配置应该声明“去哪里拿密钥”，而不是直接保存密钥本身。

## 变更内容

- 将项目统一配置中的敏感字段从 `api_key` 改为 `api_key_env`，配置文件只保存环境变量名。
- 让配置加载层在运行时解析环境变量值，并把缺失密钥视为明确的配置错误。
- 更新 planner 与 search 的配置消费逻辑，使其通过统一配置解析后的密钥运行。
- 更新示例配置、文档和测试，去除在仓库配置文件中直接保存 API key 的默认方式。

### 修改功能
- `project-config`: 统一配置中的敏感密钥字段改为环境变量名，并要求加载时解析。
- `agent-planner`: planner 必须通过统一配置解析后的环境变量密钥获取模型凭证。
- `agent-search-tool`: search 必须通过统一配置解析后的环境变量密钥获取 API 凭证。

## 影响

- 受影响代码：`trpg_py.config`、planner factory、search 默认构造、配置测试辅助、示例配置与 README。
- 受影响配置：`config/config.toml` 以及所有测试生成的项目配置样例。
- 受影响运行方式：开发者需要在环境变量中提供密钥，而不是把密钥写入配置文件。
