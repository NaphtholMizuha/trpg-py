## ADDED Requirements

### 需求:Demo 运行器必须支持单案例运行
系统必须允许调用方通过 `main.py <demo-name>` 运行单个已注册 demo 案例。每个 demo 必须关联确定性的任务文档、初始状态和固定骰子来源，以保证输出可复现。

#### 场景:运行单个演示案例
- **当** 调用方执行 `python -B main.py fireball`
- **那么** 系统运行名为 `fireball` 的 demo
- **那么** 输出中包含任务名、步骤摘要和已应用的状态变更

### 需求:Demo 运行器必须支持批量运行全部案例
系统必须允许调用方通过一个显式的批量入口一次运行全部已注册 demo 案例。批量运行必须使用稳定顺序逐个执行案例，并为每个案例输出独立摘要区块。

#### 场景:批量运行全部案例
- **当** 调用方执行 `python -B main.py all`
- **那么** 系统按稳定顺序运行全部已注册 demo
- **那么** 输出中包含每个 demo 的独立摘要区块
- **那么** 输出结尾包含整体汇总状态

### 需求:Demo 输出必须解释 skipped 与自定义布局结果
系统必须以人类可读形式展示步骤状态，包括 `success`、`failed` 和 `skipped`。当 demo 使用自定义状态布局时，输出仍必须展示真实写回路径和关键结果，而不是隐藏为默认字段名。

#### 场景:未命中导致步骤被跳过
- **当** 某个 demo 中的后续步骤因 `when` 条件为假而被跳过
- **那么** 输出中将该步骤标记为 `skipped`
- **那么** 输出仍保留前序步骤结果与最终已应用变更

#### 场景:自定义布局案例展示真实路径
- **当** 调用方运行一个使用自定义字段映射与路径模板的 demo
- **那么** 输出中展示该 demo 的步骤摘要
- **那么** 输出中的状态变更路径使用真实写回路径
