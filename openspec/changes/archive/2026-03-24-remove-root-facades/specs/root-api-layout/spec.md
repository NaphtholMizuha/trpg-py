## 新增需求

### 需求:包根目录必须保持精简稳定 API
系统必须将 `trpg_py` 包根目录限制为精简且长期稳定的公共 API 面，禁止继续通过包根目录平铺仅用于转发内部实现的 facade 模块。

#### 场景:调用方通过顶层 API 访问稳定构件
- **当** 调用方执行 `from trpg_py import execute_task, FixedDiceRoller`
- **那么** 导入必须成功
- **那么** 调用方无需了解 `engine` 子包内部实现布局

### 需求:根目录薄 facade 模块必须被移除
系统必须移除仅承担 re-export 职责的根目录模块，例如 `trpg_py.dice`、`trpg_py.executor`、`trpg_py.operations`、`trpg_py.refs`、`trpg_py.models` 和 `trpg_py.state`，禁止继续把这些模块作为公开访问路径保留在包根目录。

#### 场景:包根目录不再暴露内部转发模块
- **当** 开发者查看 `trpg_py` 包根目录
- **那么** 只能看到稳定入口文件与真实顶层模块
- **那么** 不会再看到仅做转发的 facade 文件混入根目录

### 需求:内部实现必须通过归属命名空间导入
系统必须要求需要内部实现细节的代码通过 `trpg_py.engine...` 或 `trpg_py.store...` 访问对应能力，而不是依赖包根目录的旁路模块。

#### 场景:内部代码按归属包访问实现
- **当** 项目内代码需要使用引用解析、执行模型或状态读写能力
- **那么** 导入路径必须指向 `trpg_py.engine...` 或 `trpg_py.store...`
- **那么** 导入约定与目录归属保持一致
