Plan the DM instruction into a TaskDocument for the TRPG engine.

A valid TaskDocument is an execution DSL. It is not a natural-language plan.

TaskDocument minimal shape:
{
  "task_id": "string",
  "version": 1,
  "policy": {},
  "context": {},
  "steps": [
    {
      "id": "string",
      "type": "select|check|damage|heal|resource|effect|state",
      "kind": "depends on type",
      "args": {},
      "tags": [],
      "when": null
    }
  ]
}

Allowed type/kind pairs:
- select: target | area | filtered
- check: attack | save | ability | skill
- damage: apply
- heal: apply
- resource: consume
- effect: add | remove
- state: set | adjust

Reference rules:
- Use {"$ref": "context.foo"}, {"$ref": "state.actors.hero_1.ac"}, or {"$ref": "result.attack_roll.outcome"}.
- A step may only reference results from earlier steps.
- Use "when" for conditional execution.

Path semantics:
- fetch_keys and reads use bare store paths such as actors.goblin_1.ac, actors.aldera.hp, or actors.goblin_1.attacks.scimitar.to_hit.
- Do not pass state.actors.goblin_1.ac directly to fetch_keys or reads.
- TaskDocument $ref values keep engine namespaces, so the matching reference form is state.actors.goblin_1.ac.
- Think of this as: tool path actors.goblin_1.ac -> TaskDocument $ref state.actors.goblin_1.ac.

Tool responsibilities:
- Use search for rule evidence.
- Use fetch_keys to discover candidate bare store paths.
- Use reads to confirm the current values on a small set of candidate bare store paths, such as actor ids, AC, HP, resources, or spell slots.
- Use lint to validate a candidate TaskDocument before returning status ready.

DnD5e attack reminder:
- Do not treat a natural 20 attack as an ordinary success if the plan can preserve nat semantics.
- Prefer `check.attack` with `tags=["nat"]` so the engine can emit `crit_success` or `crit_fail`.
- When a follow-up `damage.apply` depends on that attack, prefer an explicit `is_critical` mapping from the attack outcome.

Attack planning pattern:
1. Optionally select targets.
2. For DnD5e weapon or spell attacks, create a `check.attack` step that keeps `tags=["nat"]` so natural 20 and natural 1 remain visible to later steps.
3. Create a `damage.apply` step gated by the attack result.
4. If that damage comes from the attack roll, map `result.attack_roll.outcome == crit_success` into `damage.apply.is_critical` so a critical hit expands damage dice instead of acting like a normal hit.

Do not invent substitute step fields such as action, actor, target, rule, or description in place of id/type/kind/args.

Canonical example:
{
  "task_id": "goblin_scimitar_attack",
  "version": 1,
  "policy": {
    "ruleset": "dnd5e-2014"
  },
  "context": {
    "actor_id": "goblin_1",
    "target_id": "hero_1"
  },
  "steps": [
    {
      "id": "pick_target",
      "type": "select",
      "kind": "target",
      "args": {
        "source": {
          "$ref": "context.target_id"
        },
        "entity_pool": {
          "$ref": "state.actors"
        },
        "targeting": {
          "source_position": {
            "$ref": "state.actors.goblin_1.position"
          },
          "max_range": 5,
          "range_metric": "euclidean"
        }
      }
    },
    {
      "id": "attack_roll",
      "type": "check",
      "kind": "attack",
      "tags": [
        "nat"
      ],
      "args": {
        "dice": "1d20",
        "modifier": {
          "$ref": "state.actors.goblin_1.attacks.scimitar.to_hit"
        },
        "target_id": {
          "$ref": "context.target_id"
        },
        "target_ac": {
          "$ref": "state.actors.hero_1.ac"
        }
      }
    },
    {
      "id": "apply_damage",
      "type": "damage",
      "kind": "apply",
      "when": {
        "$ref": "result.attack_roll.outcome",
        "in": [
          "success",
          "crit_success"
        ]
      },
      "args": {
        "targets": {
          "$ref": "result.pick_target.target_ids"
        },
        "damage": [
          {
            "dice": "1d6",
            "bonus": 2,
            "damage_type": "slashing"
          }
        ],
        "is_critical": {
          "$ref": "result.attack_roll.outcome",
          "eq": "crit_success"
        }
      }
    }
  ]
}

Tool-path example before writing the final TaskDocument:
- fetch_keys prefix: actors
- reads paths: ["actors.goblin_1.attacks.scimitar.to_hit", "actors.aldera.ac"]
- final TaskDocument refs: {"$ref": "state.actors.goblin_1.attacks.scimitar.to_hit"} and {"$ref": "state.actors.aldera.ac"}
